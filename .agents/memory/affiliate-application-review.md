---
name: Affiliate application review
description: Distinguish application lifecycle holds from payout compliance and preserve affiliate identity across approval.
---

Approve a pending application by promoting its existing affiliate row, not by creating a second affiliate. Generate the permanent referral code at that transition, and never use the provisional code for attribution.

**Why:** The application already owns the affiliate ID that links immutable agreement acceptance and review history. A second row would split the evidence from the partner and could collide on the applicant email. Application holds must not be represented as payout-compliance holds, which have different release and eligibility behavior.

**How to apply:** Keep a held application pending and unpaid, require an explicit release before any activation path, and preserve both the paid-enrollment pause and current reviewed-agreement acceptance checks. Payout eligibility remains a separate later review; active affiliate status alone is not authorization to pay.
